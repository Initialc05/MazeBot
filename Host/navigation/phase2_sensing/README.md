# 阶段 2：雷达感墙（仿真）

用仿真雷达代替阶段 1 的"上帝视角"感知——**证明 Flood-Fill 能在真实雷达数据下跑通**。

## 模块说明

| 文件 | 做什么 |
|---|---|
| `fake_lidar.py` | 仿真雷达：输入迷宫 + 车的位置/朝向，输出 360 条"角度+距离"扫描线。支持噪声、丢点、近距离形变 |
| `wall_sense.py` | 感墙：输入雷达扫描 + 车的朝向，输出"北/东/南/西 有无墙" |
| `stress_test.py` | 压力测试：11 种噪声场景下的感墙准确率 |
| `e2e_demo.py` | 端到端：机器人从 (4,0) 走到 (2,4)，只用雷达感知 |

| 干净（无噪声） | 100% |

## 算法关键点

### 仿真雷达（`fake_lidar.py`）
从车的位置往 360 个方向打射线，找第一个碰到的墙。加三种可选失真：
- **高斯噪声**（σ 可配）
- **近距离形变**（距离 < 阈值时乘 0.85 左右，模拟 C1 近距测量误差）
- **随机丢点**（模拟质量不佳的光束被丢弃）

### 感墙（`wall_sense.py`）

对北/东/南/西四个方向，每个方向取**±30° 扇区**内所有光束，算**中位数距离**。如果 < 22 cm（半格 + 少量 slack），判定"这边有墙"。

为什么用这两个选择：
- **扇区而非单点**：单点可能打穿门缝
- **中位数而非平均**：抗离群值（丢点和噪声尖峰）

实测：22 个阈值 + 30° 扇区 + 中位数的组合，对任何程度的噪声都 100% 稳

### 接口：用阶段 1 的代码完全不改

`e2e_demo.py` 的主循环：
```python
scan = simulate_scan(...)              # 仿真雷达
walls = sense_walls(scan, heading)     # 感墙
update_belief(belief, pos, walls)      # 更新信念地图
dist = flood_fill(belief, goal)        # 算距离场（阶段 1 的代码）
next_dir = choose_next_move(...)       # 选方向（阶段 1 的代码）
# 移动到下一格
```

**阶段 1 的 `flood_fill()` 和 `choose_next_move()` 一行都没改**——证明分层设计正确。

## 已知限制

- 车还是"瞬移"到下一格，**没有真实运动学**。阶段 3 处理
- 感墙假设车在**格子正中心**——如果在格子里歪一点，可能判错
- **没有尺度标定**——`CELL_SIZE_M = 0.30` 是假设，真实迷宫要测
